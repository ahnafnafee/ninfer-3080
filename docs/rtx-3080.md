# RTX 3080 (10 GB) on Windows

NInfer-3080 is the [NInfer-3090 consolidated line](https://github.com/iamwavecut/ninfer-3090) with
the changes a 10 GB RTX 3080 on native Windows needs. Every number below was measured on one card:
RTX 3080 10 GB (68 SMs, 320 W), Intel Core i9-14900K, Windows 11, CUDA 13.1, one request at a time,
`temperature=1.0`, `top_p=0.95`, `top_k=20`, a desktop monitor attached to the same card.

## What changes against NInfer-3090

- **The Windows build compiles with MSVC.** The NVFP4 divisor epilogue called `__builtin_ctz` in
  host code, which MSVC does not have; it now uses C++20 `std::countr_zero`.
- **`scripts\build.ps1` finds the toolchain on a normal workstation.** It searches VS 2022
  Community, Professional and Enterprise where they install (`Program Files`), takes the oldest CUDA
  toolkit at or above 12.8 (so 13.x works), and passes vcpkg's CMake toolchain from
  `CMAKE_TOOLCHAIN_FILE`, `VCPKG_ROOT` or a `vcpkg.exe` on `PATH`.
- **A built-in RTX 3080 device profile** (10 GB, 68 SMs), so the card starts on measured routes
  instead of calibrating on first launch. The 12 GB RTX 3080 has 70 SMs and still calibrates.
- **`--kv-headroom-mib` is listed in `--help`.** `--kv-capacity auto` holds back 1 GiB by default,
  which a 10 GB card cannot spare.
- **`tools\windows\ninfer-switch`**: start, switch, stop and inspect a serving profile from any
  terminal.

## Which model fits

A 4-bit Qwen3.8-27B artifact is 19 GiB and NInfer has no weight offload, so on 10 GB the model is
**Ternary Bonsai 2 27B**, PrismML's ternary retrain of Qwen3.8-27B: 6.70 GiB of text weights, plus
0.42 GiB for its MTP head.

- Uncensored (Heretic): [emiltsoi/Ternary-Bonsai-2-27B-Uncensored-Heretic-NInfer](https://huggingface.co/emiltsoi/Ternary-Bonsai-2-27B-Uncensored-Heretic-NInfer)
- Official: [WaveCut/Ternary-Bonsai-2-27B-NInfer-v3](https://huggingface.co/WaveCut/Ternary-Bonsai-2-27B-NInfer-v3)

Both are 8.87 GiB files that also carry Vision and a DFlash2 adapter; the server loads only what its
flags ask for. DFlash2 does not fit next to any useful context on 10 GB.

## Measured

| Profile | KV | Window | Short answers | Nearly full | Prompt |
|---|---|---:|---:|---:|---:|
| `mtp`: MTP, 3 drafts | `rk2v4-e8` | 65,536 | 139 reasoning / 98 code tok/s | 94 tok/s at 61,602 | 1,630 tok/s |
| `96k`: no speculation | `rk2v4-e8` | 98,304 | 70 tok/s | 53 tok/s at 91,837 | 1,420 tok/s |
| `mtp48`: MTP, 3 drafts | `rk4v4` | 49,152 | 137 / 94 tok/s | 106 tok/s at 28,973 | 1,900 tok/s |
| no speculation | `rk4v4` | 65,536 | 72 tok/s | 65 tok/s at 28,973 | 1,940 tok/s |

Limits on this card:

- **MTP at 76K does not start**: the runtime reservation comes up about 120 MB short. 64K is the
  largest MTP window.
- **Without speculation, speed sets the limit, not memory.** A 104K window starts, but decode falls
  to 49.7 tok/s at 99,391 tokens, so 96K is the largest window that stays above 50 tok/s when full.
- **`rk2v4-e8` buys 23% more tokens than `rk4v4`** for a quality cost: quick-corpus perplexity on
  Ternary Bonsai 2 moves from 5.631 to 5.820 (from the NInfer-3090 reference measurements).

For comparison on the same card, PrismML's llama.cpp fork serving the same ternary weights reached
48-58 tok/s on short answers and 38-44 tok/s at 29K, and a 4-bit Qwen3.8-27B GGUF split between the
GPU and system RAM reached about 5 tok/s.

## Memory on a desktop card

The server plans every byte at startup and never grows, but Windows keeps its own allocations on the
same card: a monitor attached to the 3080 costs 0.4 to 1.1 GB depending on what is open. With a
server of another engine on this card, about 100 MB of free VRAM was enough for WDDM to move
allocations into system RAM and cut decode by 30 to 90% without any error. Plugging the monitor into
the motherboard's integrated graphics returns that memory to the model.

## Build

Requirements: VS 2022 with "Desktop development with C++" (MSVC 14.4x), CUDA 12.8 or newer, CMake,
Ninja, and a [vcpkg](https://github.com/microsoft/vcpkg) checkout.

```powershell
git clone https://github.com/microsoft/vcpkg C:\src\vcpkg
C:\src\vcpkg\bootstrap-vcpkg.bat -disableMetrics
$env:VCPKG_ROOT = 'C:\src\vcpkg'
.\scripts\build.ps1
```

The first configure builds FFmpeg and libcurl through vcpkg (about 10 minutes, then cached). The
server lands in `build-ninja\apps\ninfer-serve.exe`.

## Serve with ninfer-switch

Put the artifact in `models\` (or point `NINFER_MODELS` at its folder) and add `tools\windows` to
`PATH`. Then, from any terminal:

```text
ninfer-switch mtp        start or switch to a profile (hidden, survives closing the terminal)
ninfer-switch status     profile, uptime, port owner, served model, GPU memory, KV capacity, last rate
ninfer-switch logs -f    follow the server log
ninfer-switch kill       stop it
ninfer-switch start      start the last profile again
ninfer-switch list       profiles and what they are for
```

The API is OpenAI and Anthropic compatible at `http://127.0.0.1:8080/v1`, model id
`bonsai2-heretic`. Profiles live in `tools\windows\profiles.json`. A second file named by
`NINFER_PROFILES` adds or replaces profiles and can set `"port"` and `"models"`, so local servers of
other engines can sit behind the same command. The tool only stops server binaries it can start: if
another program owns the port it says so and leaves it alone.
